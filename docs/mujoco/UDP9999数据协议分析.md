# UDP 9999 端口数据协议分析

> 基于 MuJoCo 模式下 robot_mujoco → UE 的 UDP 9999 抓包分析

## 一、基本信息

| 属性 | 值 |
|------|-----|
| 发送方 | robot_mujoco（动态源端口） |
| 接收方 | UE（监听端口 9999） |
| 协议 | UDP |
| 包大小 | **412 bytes**（固定） |
| 频率 | ~100Hz（每 10ms 一包） |
| 字节序 | Little-Endian |
| 数据类型 | IEEE 754 double (float64) |

## 二、数据结构

```
┌─────────────────────────────────────────────────────────┐
│ 偏移 0   │ double  │ sim_time    │ 仿真时间戳 (秒)       │  8 bytes
├─────────────────────────────────────────────────────────┤
│ 偏移 8   │ int32   │ nq = 19     │ qpos 向量长度         │  4 bytes
├─────────────────────────────────────────────────────────┤
│ 偏移 12  │ 19×double │ qpos      │ MuJoCo 位置向量       │ 152 bytes
├─────────────────────────────────────────────────────────┤
│ 偏移 164 │ int32   │ nv = 18     │ qvel 向量长度         │  4 bytes
├─────────────────────────────────────────────────────────┤
│ 偏移 168 │ 18×double │ qvel      │ MuJoCo 速度向量       │ 144 bytes
├─────────────────────────────────────────────────────────┤
│ 偏移 312 │ int32   │ nu = 12     │ 电机数量              │  4 bytes
├─────────────────────────────────────────────────────────┤
│ 偏移 316 │ 12×double │ tau       │ 电机扭矩 (Nm)         │  96 bytes
└─────────────────────────────────────────────────────────┘
总计: 8 + 4 + 152 + 4 + 144 + 4 + 96 = 412 bytes
```

## 三、各字段详解

### 3.1 sim_time（偏移 0，8 bytes）

MuJoCo 仿真时间戳，单位秒，double 精度。

### 3.2 qpos — 位置向量（偏移 12，19 × 8 = 152 bytes）

对应 MuJoCo 的 `mjData->qpos`，即模型的完整位置状态：

| 索引 | 含义 | 偏移 | 说明 |
|------|------|------|------|
| qpos[0] | base_x | 12 | base_link X 坐标 (m) |
| qpos[1] | base_y | 20 | base_link Y 坐标 (m) |
| qpos[2] | base_z | 28 | base_link Z 坐标 (m) |
| qpos[3] | quat_w | 36 | 四元数 W 分量 \| **\|q\| = 1.0** |
| qpos[4] | quat_x | 44 | 四元数 X 分量 \| |
| qpos[5] | quat_y | 52 | 四元数 Y 分量 \| |
| qpos[6] | quat_z | 60 | 四元数 Z 分量 \| |
| qpos[7] | FR_abad | 68 | 右前 外展关节 (rad) |
| qpos[8] | FR_hip | 76 | 右前 髋关节 (rad) |
| qpos[9] | FR_knee | 84 | 右前 膝关节 (rad) |
| qpos[10] | FL_abad | 92 | 左前 外展关节 (rad) |
| qpos[11] | FL_hip | 100 | 左前 髋关节 (rad) |
| qpos[12] | FL_knee | 108 | 左前 膝关节 (rad) |
| qpos[13] | RR_abad | 116 | 右后 外展关节 (rad) |
| qpos[14] | RR_hip | 124 | 右后 髋关节 (rad) |
| qpos[15] | RR_knee | 132 | 右后 膝关节 (rad) |
| qpos[16] | RL_abad | 140 | 左后 外展关节 (rad) |
| qpos[17] | RL_hip | 148 | 左后 髋关节 (rad) |
| qpos[18] | RL_knee | 156 | 左后 膝关节 (rad) |

**关节顺序**：FR → FL → RR → RL（右前→左前→右后→左后），每条腿 abad→hip→knee。

### 3.3 qvel — 速度向量（偏移 168，18 × 8 = 144 bytes）

对应 MuJoCo 的 `mjData->qvel`，即模型的完整速度状态：

| 索引 | 含义 | 偏移 | 说明 |
|------|------|------|------|
| qvel[0] | vx | 168 | base_link X 线速度 (m/s) |
| qvel[1] | vy | 176 | base_link Y 线速度 (m/s) |
| qvel[2] | vz | 184 | base_link Z 线速度 (m/s) |
| qvel[3] | wx | 192 | base_link X 角速度 (rad/s) |
| qvel[4] | wy | 200 | base_link Y 角速度 (rad/s) |
| qvel[5] | wz | 208 | base_link Z 角速度 (rad/s) |
| qvel[6:18] | joint_vel | 216-304 | 12 路关节角速度 (rad/s) |

### 3.4 tau — 电机扭矩（偏移 316，12 × 8 = 96 bytes）

12 路电机输出扭矩，单位 Nm。顺序同 qpos[7:19]。

## 五、与 MuJoCo 模型的对应关系

| MuJoCo 参数 | 值 | 对应数据段 |
|------------|-----|-----------|
| `nq` | 19 | qpos（7 自由关节 + 12 腿关节） |
| `nv` | 18 | qvel（6 自由关节 + 12 腿关节） |
| `nu` | 12 | tau（12 路电机） |
| `nbody` | 14 | 不直接传输（UE 通过 FK 计算） |

**关键**：这个数据包就是 MuJoCo 的 **完整仿真状态**（qpos + qvel）加上电机扭矩（tau）。UE 接收后写入自己的 `mjData->qpos`，调用 `mj_kinematics()` 做 FK，然后更新 mesh 位置。

## 六、UE 侧处理流程（推测）

```
UDP 9999 接收 412 bytes
        │
        ▼
解析 qpos[19] → 写入 mjData->qpos
        │
        ▼
mj_kinematics() → 正向运动学
        │
        ▼
更新所有 body 的 mesh transform
        │
        ▼
渲染帧输出 (30 FPS)
```

## 七、对 CarlaUnreal 的意义

CarlaUnreal 要实现相同的外部物理渲染模式，需要：

1. **监听 UDP 9999**，接收 412 bytes 数据包
2. **解析 qpos** → 写入内部 MuJoCo 的 `mjData->qpos`
3. **调用 mj_kinematics()** → 计算 FK
4. **更新 mesh transform** → 渲染

可选：同时解析 qvel 和 tau 用于其他用途（如速度显示、力反馈等）。





根据之前的抓包分析，UDP 9999 的数据结构已经清楚了。UE 的使用方式是：

**UE 作为纯渲染器，接收 qpos → 直接设置 mesh transform**

具体流程：

```
UDP 9999 收到 412 bytes
    ↓
解析出 qpos[19]:
  [0:3]   = base位置 (x, y, z)
  [3:7]   = base四元数 (w, x, y, z)
  [7:19]  = 12个关节角度
    ↓
方式A（Matrix的做法，最可能）：
  直接对每个 body 设置 SetWorldLocation/Rotation
  不需要 mj_kinematics，因为 qpos 已经包含了所有信息
  base_link → SetWorldTransform(pos, quat)
  每个关节 → 根据关节角度计算子 body 的世界变换

方式B（理论上也可以）：
  写入 mjData->qpos → 调 mj_kinematics() → 读取 body pos/quat → 更新 mesh
```

**方式A 更可能**，因为：
- UE 是游戏引擎，直接设置 transform 是最自然的做法
- 不需要在 UE 里链接 MuJoCo 库
- 12 个关节角度 + base pose 足够直接算出每个 body 的世界坐标

**关键点**：UE 不跑 `mj_step`，不做物理仿真，只是把收到的 qpos "画"出来。物理计算全在 robot_mujoco 进程里完成。
