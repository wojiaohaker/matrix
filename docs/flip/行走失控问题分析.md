# 机械狗行走失控问题分析

## 问题描述

mujoco_sim 按 W 键行走时，机器人立即出现剧烈抖动/失控，2秒内完全翻转。

- **`v_world_x` 从 0 跳到 0.736 m/s** — 位置几乎没变，速度突然出现！

## 根因分析

### 因果链

```
1. cmd_vel 从 0 变为行走指令
       ↓
2. RL walk policy 输出新 q_des（轻微偏离站立平衡点）
   - q_des_abad: 0.138 → 0.106（仅 1.8 度）
       ↓
3. PD 控制器执行 → 物理系统产生响应
       ↓
4. framelinvel 传感器检测到 v_world_x = 0.736 m/s
   ★ 关键异常：base_x 仅变化 0.000005，速度却出现 0.736 m/s
       ↓
5. LSTM 隐状态（已适应 191 秒零速度输入）突然看到非零速度
   → 分布外输入 → 隐状态快速漂移
       ↓
6. 2~3 步后策略输出极端值（q_des_abad = ±23 rad）
       ↓
7. kp=20 无法跟踪极端目标 → 关节速度爆炸（±100+ rad/s）
       ↓
8. RL_FlipOver 反复触发但无法恢复 → 死循环
```

### 核心疑点：v_world 异常跳变

**数据矛盾**：
- `base_x` 变化 = 0.000005 m（100 步累积位移）
- `v_world_x` = 0.736 m/s（瞬时速度）

如果速度是真实的，100 步（0.1s）内位移应约 0.07m，但实际仅 0.000005m。

**传感器来源**：
```xml
<!-- xgb.xml -->
<framelinvel name="frame_vel" objtype="site" objname="imu" />
```

MuJoCo `framelinvel` 输出的是 **世界坐标系** 线速度。

**当前代码**（mujoco_sim.cpp BuildRobotState）：
```cpp
// v_world: 直接发布世界坐标系线速度 (与 robot_mujoco 一致)
state.add_v_world(shared_state_.base_linvel[0]);  // 世界系，未转换
```

### 可能的根因方向

| # | 假设 | 说明 |
|---|------|------|
| 1 | v_world 坐标系不匹配 | RL 策略训练用 body-frame 速度，但收到 world-frame 速度 |
| 2 | LSTM 隐状态累积漂移 | 191 秒站立期间隐状态已偏离训练分布 |
| 3 | MuJoCo 数值瞬变 | PD 控制器执行微小 q_des 变化时产生速度脉冲 |
| 4 | 站立→行走转换时未重置 LSTM | 策略需要干净的初始隐状态 |

## 根因分析（更新）

### 核心发现：ApplyControl 与原始 Matrix 实现的关键差异

**mujoco_sim ApplyControl（当前代码）：**
```cpp
tau = kp*(q_des - q) + kd*(qd_des - qd) + tau_ff + qfrc_bias;
// 无扭矩限幅！
```

**原始 Matrix zsibot_mujoco_ue / CarlaUnreal ApplyUdpControl：**
```cpp
torque = kp * (target - current) - kd * currentVel + tau_ff;
mData->ctrl[mjIdx] = Clamp(torque, -28.0f, 28.0f);  // ±28 Nm 限幅
// 无 qfrc_bias！
```

**两个关键差异：**

| 差异 | mujoco_sim | 原始 Matrix | 影响 |
|------|-----------|------------|------|
| 重力补偿 | **有** (qfrc_bias) | **无** | RL 策略在「低重力」环境下训练，部署后行为不匹配 |
| 扭矩限幅 | **无** | **±28 Nm** | 极端扭矩无限制地施加到关节 |

### 完整因果链（更新）

```
1. RL_MIX 进入，RL_Walk 策略开始输出
       ↓
2. 策略输出 2.6 秒内看似合理（q_des 缓慢漂移）
       ↓
3. LSTM 隐状态逐渐漂移到训练分布边缘
       ↓
4. 策略输出一个较大的 q_des 变化（FR_knee: -1.291 → -1.013，Δ=0.278 rad）
       ↓
5. PD 控制产生位置误差扭矩 + qfrc_bias 在倾斜姿态下放大
   → FR_knee ctrl = 39 Nm（远超 ±28 Nm 安全范围！）
       ↓
6. 关节速度爆炸（knee qd = -31.68 rad/s，超过 jointVelocityLimit=24）
       ↓
7. 正反馈循环：更大倾斜 → 更大 qfrc_bias → 更大扭矩 → 更快倾斜
       ↓
8. 0.4 秒内完全失控
```

### 数值验证

在 step 24800（发散点）：
- FR_knee: q=-0.913, q_des=-0.809, qd=-31.68
- PD 扭矩: 20×(-0.809-(-0.913)) + 0.7×(0-(-31.68)) = 2.08 + 22.18 = **24.26 Nm**
- qfrc_bias: 39.06 - 24.26 = **14.8 Nm**（额外重力补偿项！）
- 原始 Matrix（无 qfrc_bias）: 仅 **24.26 Nm**（在 ±28 Nm 安全范围内）
- mujoco_sim（有 qfrc_bias）: **39.06 Nm**（超出安全范围 39%！）

### 额外发现的根因（P1~P3）

除 qfrc_bias 外，还发现以下问题共同导致失控：

**P1: STANDUP→RL_MIX 转换时关节偏差过大**

从 mujoco_diag.log step 23200（RL_MIX 进入瞬间）：
```
FR hip:  q=0.795, q_des=0.691  → 偏差 0.60 rad（34°）
FR knee: q=-1.552, q_des=-1.524 → 偏差 0.88 rad（50°）
base_z=0.319（目标约 0.32）
```
机器人在关节偏离目标 30~50° 时就进入了行走策略。RL walk policy 训练时的 nominal standing pose 与实际初始姿态差异巨大，策略从一开始就在分布外运行。

**P2: LSTM 隐状态未重置**

mc_ctrl 在 2.6 秒（step 23200~24500）的 RL_MIX 期间，LSTM 512 维隐状态持续累积。diag 数据显示 q_des 在缓慢漂移（FR_knee qdes: -1.235 → -1.291），这正是 LSTM 隐状态漂移的表现。当漂移到达临界点（step 24600），策略输出突变。

**P3: kp 阶跃下降（80→20）无过渡**

STANDUP 用 kp=80 维持姿态，进入 RL_MIX 瞬间 kp 直接降到 20。控制力突然减弱为原来的 1/4，产生初始扰动。

### 完整因果链（更新）

```
1. STANDUP kp=80 强制接近目标（但仍有 30~50° 偏差）
       ↓ kp 骤降到 20
2. RL_MIX 启动，关节在松散控制下开始运动
       ↓ LSTM 隐状态从 0 累积（未重置）
3. 2.6 秒内 q_des 缓慢漂移（LSTM 分布外运行）
       ↓ 策略输出突变
4. PD 扭矩 + qfrc_bias 放大 → ctrl=39 Nm（超 ±28 Nm）
       ↓ 正反馈
5. 0.4 秒内关节速度爆炸 → 完全失控
```

## 建议修复方案（更新优先级）

### 方案 A：移除 qfrc_bias + 添加扭矩限幅（P0，最高优先级）

修改 mujoco_sim ApplyControl()，与原始 Matrix 保持一致：
```cpp
// 修改后:
tau = kp*(q_des - q) + kd*(qd_des - qd) + tau_ff;
tau = std::clamp(tau, -28.0, 28.0);  // ±28 Nm 限幅
```

### 方案 B：速度指令平滑过渡（P3）

不要从 0 直接跳到目标速度，用 ramp 在 0.5~1s 内渐增。

### 方案 C：站立→行走转换时重置 LSTM 隐状态（P2）

在 FSM 切换时将 h0/c0 清零。

### 方案 D：增加行走初期 PD 增益（备选）

过渡期使用 kp=40~60，增强跟踪能力。
