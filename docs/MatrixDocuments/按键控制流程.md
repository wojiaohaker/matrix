## 是的，按键控制**必须经过 mc_ctrl**

从日志中可以看到，Matrix 的按键并不是直接发给 UE 的：

```
[KeyListener] XGrabKey grabbed keysym: w    ← 全局键盘钩子（X11级别）
[KeyListener] XGrabKey grabbed keysym: a
[KeyListener] XGrabKey grabbed keysym: s
[KeyListener] XGrabKey grabbed keysym: d
[KeyListener] XGrabKey grabbed keysym: q
[KeyListener] XGrabKey grabbed keysym: e
[KeyListener] XGrabKey grabbed keysym: space
```

### Matrix 按键控制的完整数据流

```
┌──────────────────────────────────────────────────────────────────┐
│  你按下 W 键                                                      │
│       │                                                          │
│       ▼                                                          │
│  sim_launcher.bin (Qt GUI)                                       │
│  ├── XGrabKey 全局拦截键盘（UE 窗口根本收不到按键！）               │
│  ├── 转换为速度指令: vx=1.0, vy=0, vyaw=0                       │
│  └── 发送给 mc_ctrl（通过 ROS2/zenoh 或 UDP）                     │
│       │                                                          │
│       ▼                                                          │
│  mc_ctrl (RL 大脑)                                               │
│  ├── 收到速度指令 (vx, vy, vyaw)                                 │
│  ├── 读取当前状态（从 UE 的 25001 端口）                          │
│  ├── RL 策略推理: f(状态, 指令) → 12个关节目标角度                │
│  └── UDP :25002 发送关节目标给 UE                                 │
│       │                                                          │
│       ▼                                                          │
│  UE (zsibot_mujoco_ue)                                           │
│  ├── 收到 12 个关节目标角度                                       │
│  ├── PD 控制: torque = Kp×(目标-当前) - Kd×速度                  │
│  ├── mj_step() 物理仿真                                          │
│  └── 渲染画面                                                    │
└──────────────────────────────────────────────────────────────────┘
```

### 关键证据

1. **XGrabKey 是 X11 全局钩子** — 按键被 `sim_launcher.bin` 截获，UE 根本不知道有按键事件
2. **UE 没有键盘控制逻辑** — UE 只监听 UDP 25002 端口，被动接收关节指令
3. **mc_ctrl 绑定 CPU 核心 7** (`taskset -c 7`) — 保证 RL 推理实时性

### 和你的对比

|                 | Matrix                   | 你的 MuJoCoUE         |
| --------------- | ------------------------ | --------------------- |
| 按键捕获        | sim_launcher (X11全局)   | UE 内部 (PlayerInput) |
| 速度指令→关节角 | **mc_ctrl (RL神经网络)** | 手写 IK 公式          |
| PD 控制         | UE 内部                  | UE 内部               |
| 物理仿真        | UE 内嵌 MuJoCo           | UE 内嵌 MuJoCo        |

**本质区别只有一步**：Matrix 用 RL 把"前进1m/s"翻译成12个协调的关节角，你用的是手写 IK 公式。其余（PD、物理、渲染）完全相同。

所以你在 UE 里按键 → 直接算 IK → 直接驱动，**跳过了 mc_ctrl 这一层"大脑"**，这就是效果差距的来源。
